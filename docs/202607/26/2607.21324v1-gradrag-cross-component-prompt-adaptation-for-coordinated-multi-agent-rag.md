## 摘要
检索增强生成（RAG）系统日益采用多个大语言模型（LLM）智能体。然而，多数先前工作孤立地优化各组件，而非跨流水线协调改进。我们提出GRADRAG，一个跨组件提示自适应框架，将RAG流水线建模为计算图，并传播结构化评估反馈以更新上游智能体。评估器评判下游答案及其支撑证据，生成可操作的反馈，提示优化器据此迭代更新自适应智能体，如检索器、图构建器和回答器。当输出被视为满意时，评估器还会触发提前停止。我们在SQUALITY和QMSUM基准上，针对两种检索范式评估GRADRAG：基于扁平分块的IRCoT式查询细化检索（Trivedi et al., 2023），以及从文档构建并逐步扩充实体关系图的图检索。在这两种设置下，GRADRAG始终优于仅更新最终生成器的一步细化基线，在LLM判别的成对比较中取得12-15个百分点的净偏好优势，且大部分提升在两轮细化内实现。

## Abstract
Retrieval-Augmented Generation (RAG) systems increasingly employ multiple LLM agents. Yet, most prior work optimizes components in isolation rather than coordinating improvements across the pipeline. We introduce GRADRAG, a framework for cross-component prompt adaptation that models the RAG pipeline as a computational graph and propagates structured evaluation feedback to update upstream agents. An Evaluator critiques downstream answers and supporting evidence, producing actionable feedback that a Prompt Optimizer uses to iteratively update adaptive agents, such as retrievers, graph constructors, and answerers. The Evaluator also triggers early stopping when the output is deemed satisfactory. We evaluate GRADRAG on the SQUALITY and QMSUM benchmarks under two retrieval paradigms: flat chunk-based retrieval using IRCoT-style query refinement (Trivedi et al., 2023), and graph-based retrieval that constructs and iteratively enriches an entity-relation graph from the document. Across both settings, GRADRAG consistently outperforms one-step refinement baselines that update only the final generator, achieving a 12-15 percentage point net preference margin in LLM-judged pairwise comparisons, with most gains realized within two refinement iterations.

*   **核心问题**：当前多智能体（Multi-Agent）RAG 系统普遍存在一个**协调问题（Coordination Problem）**。优化工作往往是孤立的（例如仅优化查询重写、证据过滤或最终答案的自我反思），导致流水线早期阶段产生的错误（如检索不全、证据结构混乱）会向下游传播，限制整体性能。最终答案的评估信号很少被用来改进上游组件（如检索器、图构建器）。
*   **研究动机**：论文旨在弥合这一鸿沟，探索如何利用下游答案质量的反馈，以统一的方式自适应地调整 RAG 流水线中的多个上游组件，从而实现协同改进。
*   **整体含义**：论文并非提出一种全新的 RAG 架构，而是提出一个**通用的、与检索范式无关的框架**，用于在模块化、多智能体的 RAG 系统中协调各组件的提示优化，提升端到端的输出质量。

### 2. 论文提出的方法论

论文提出了 `GRAD RAG`（**Grad**ient-based **R**etrieval-**A**ugmented **G**eneration），一个在测试时通过跨组件提示自适应来协调多智能体 RAG 的框架。

*   **核心思想**
    *   **计算图抽象**：将 RAG 流水线建模为一个计算图，节点代表检索器、图构造器、答案生成器等智能体。这些智能体关联的提示（prompt）可以是固定的，也可以是**自适应的**。
    *   **跨组件反馈传播**：与仅优化最终答案的单步反思方法不同，`GRAD RAG` 将评估器对最终答案和支撑证据的批判性反馈，传播给多个上游自适应智能体，用于更新它们的提示。
    *   **迭代细化与早停**：整个过程在测试时以迭代循环方式执行：`前向传播 -> 评估 -> 提示优化 -> 下一轮前向传播`。当评估器判断输出满意时，循环提前终止。

*   **关键技术细节与流程**
    `GRAD RAG` 的迭代细化流程（总结自 Algorithm 1）如下：

    1.  **前向传播**：使用当前提示执行 RAG 流水线，生成中间产物（如检索到的文本块或抽取的实体关系图），并生成最终答案 \( y_t \)。
    2.  **评估**：**评估器（Evaluator）** 智能体审查生成的答案 \( y_t \) 及其支撑证据，并生成结构化的文本反馈 \( f_t \) 和一个二值决策 \( d_t \)（`SATISFACTORY` 或 `NEEDS_REFINEMENT`）。
    3.  **决策与早停**：如果 \( d_t = \text{SATISFACTORY} \)，则返回 \( y_t \)，流程结束。否则，进入下一步。
    4.  **提示自适应**：一个**提示优化器（Prompt Optimizer）** 智能体将反馈 \( f_t \) 转换为具体的提示更新指令，并修改流水线中所有**自适应智能体**的提示。
    5.  **循环**：使用更新后的提示，开始下一轮（t+1）迭代，直到达到最大迭代次数 \( T \) 或触发早停。

*   **在两种检索范式下的实例化**
    *   **Flat (Vector) RAG**：自适应智能体是**检索智能体（Retrieval Agent）** 和**答案生成智能体（Answer Generation Agent）**。反馈可促使检索智能体生成更有针对性的子查询。
    *   **Graph RAG**：自适应智能体是**图抽取智能体（Graph Extraction Agent）** 和**答案生成智能体**。反馈可引导图抽取智能体去优先发现对回答问题最有用的实体和关系，动态形成一种任务导向的“本体”。
