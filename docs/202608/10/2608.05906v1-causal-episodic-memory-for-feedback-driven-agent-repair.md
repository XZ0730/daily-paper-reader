## 摘要
修复失败的大语言模型智能体常常丢弃成功的修正，迫使后续情节重新发现类似的解决方案。我们研究最终化的修复结果能否在无需参数更新的情况下改善后续的文本到SQL任务情节。我们提出MERIT，这是一个无需训练的智能体，它维护一个在线双极性记忆，记录经预言机验证的修正和观察到的不成功方向。在预言机辅助的基准反馈下，只有来自较早已完成情节的记忆才符合检索条件。一个确定性分类器分配粗略的失败类型，该类型在冻结模型生成每次修订之前调节一个混合词法-稠密检索器。使用Qwen2.5-7B-Instruct，在相同的初始预测和修复预算下，MERIT将无状态迭代修复的执行准确率在Spider上从66.34%提高到69.79%，在BIRD上从47.35%提高到48.44%。配对分析为Spider的提升提供了明确证据，但在BIRD上证据较弱。在两个基准上，MERIT都无法可靠地与无类型动态检索区分开，而Reflexion风格的内存以显著更高的推理成本在BIRD上达到51.24%。消融实验表明，负面记忆贡献适度，类型调节和词法-稠密排序的价值依赖于数据集，而模式本地经验提供了最一致的好处。这些结果阐明了在何种情况下因果跨查询记忆改善修复，以及何时更广泛的内存表示仍然更可取。

## Abstract
LLM agents that repair failures often discard successful corrections, forcing later episodes to rediscover similar solutions. We study whether finalized repair outcomes can improve subsequent Text-to-SQL episodes without parameter updates. We introduce MERIT, a training-free agent that maintains an online dual-polarity memory of oracle-verified corrections and observed unsuccessful directions. Under oracle-assisted benchmark feedback, only memories from earlier finalized episodes are eligible for retrieval. A deterministic classifier assigns a coarse failure type, which conditions a hybrid lexical-dense retriever before the frozen model generates each revision. Using Qwen2.5-7B-Instruct with identical initial predictions and repair budgets, MERIT improves execution accuracy over stateless iterative repair from \(66.34\%\) to \(69.79\%\) on Spider and from \(47.35\%\) to \(48.44\%\) on BIRD. Paired analyses provide clear evidence for the Spider gain but weaker evidence on BIRD. MERIT is not reliably separated from untyped dynamic retrieval on either benchmark, while Reflexion-style memory reaches \(51.24\%\) on BIRD at substantially higher inference cost. Ablations show that negative memory contributes modestly, the value of type conditioning and lexical--dense ranking is dataset dependent, and schema-local experience provides the most consistent benefit. These results clarify when causal cross-query memory improves repair and when broader memory representations remain preferable.

### 论文核心问题与整体含义
该论文研究**大语言模型智能体在修复文本到SQL（Text-to-SQL）任务失败时，能否通过跨查询的经验记忆提升后续修复能力**。现有方法（如Self-Debugging、Reflexion等）大多把每次查询视为新问题，丢弃了之前的成功修正，导致相似失败不断被重新探索。作者提出的核心问题是：**在不更新模型参数的前提下，利用以往情节中已验证的修复结果（因果情景记忆）能否可靠地改善后续修复效果**。这意味着每当一个查询的修复被确认成功或失败，该经验才会变为对后续查询可见的记忆，形成一种“因果”在线学习。

### 方法论核心思想与技术细节

#### 总体框架：MERIT
- MERIT（Memory-Augmented Error-Typed Retrieval for Iterative Text-to-SQL repair）是一个**无需训练**的智能体，在在线修复过程中积累结构化经验，并用条件检索指导冻结模型生成修正。
- 核心组件：
  - **因果在线修复流**：对于每个查询，先用冻结模型生成共享的初始SQL。若初始预测错误，则在给定的修复预算内（K=7）重复修复循环，且只能从**更早完成的情节**中检索记忆。
  - **确定性错误分类器**：根据执行状态和数据库错误文本，将当前失败的SQL映射为预定义的失败类型（如`SCHEMA LINKING`、`SYNTAX`、`RESULT MISMATCH`等），作为检索的粗粒度先验。
  - **在线双极性记忆**：将之前情节的修复经验分为两类：
    - **正向记忆**：记录一条从失败SQL到被预言机确认为正确的SQL的转换。
    - **负向记忆**：记录一个最终失败的方向（即最后尝试却未成功的修复尝试）。
  - **类型条件的混合检索**：检索仅在同一极性池内进行，优先选择与当前失败类型相同的条目（当该类型条目≥3，否则回退到全部合法记忆）。使用**稠密（dense）相似度（75%）和词法（BM25）相似度（25%）** 的混合排名，分别独立归一化后加权排序。
  - **修复生成**：将当前问题、模式、错误上下文、本地尝试历史和检索到的记忆组成提示，让冻结模型生成一个新的SQL查询修复。
  - **情节终结与记忆更新**：若修复成功，存入一条正向记忆；若预算耗尽仍未成功，存入一条负向记忆。当前查询的中间尝试不会被存入全局记忆。

#### 变体
- **类型可靠性感知检索（Type-Reliability-Aware）**：仅对高可靠性类型（如`SYNTAX`等）使用硬过滤，对其他类型则使用类型匹配作为排序软加成。
- **对比方法**：
  - **Iterative**：仅用执行反馈和当前情节历史，无全局记忆。
  - **Dynamic RAG**：累积经历但不分极性、不使用硬类型条件。
  - **Reflexion-style**：在修复中加入从失败尝试衍生的语言反思。

### 主要结论与发现
- **因果跨查询记忆总体上改善了修复**：
  - 在Spider上，MERIT比无记忆的Iterative提高了3.45个百分点（66.34%→69.79%），置信区间明确为正。
  - 在BIRD上，改善仅1.09个百分点（47.35%→48.44%），证据较弱。
- **结构化记忆并不必然优于更简单的动态记忆**：MERIT与Dynamic RAG在准确率上没有可靠差异，两者在Spider上持平，在BIRD上MERIT仅略有优势（0.28pp）。

- **消融实验揭示**：
  - **负向记忆贡献很小**：移除负向记忆只导致轻微下降（<0.2pp）。
  - **类型条件与混合排名的价值依赖数据集**：Spider上类型过滤和稠密重排更重要，BIRD上词法与稠密的作用互换。

- **推理成本**：MERIT虽然修复成功率更高，但总令牌消耗比无记忆修复更高（因为记忆扩充了提示长度）。

### 优点（亮点）
- **无需训练**的在线记忆框架，可直接应用于任意冻结模型，简易部署。

- **双极性记忆与错误类型引导检索**的设计新颖且具可解释性。

### 不足与局限
- **依赖语言机标识**：需要细粒度的正确性信号（denotation match），现实部署中通常只能获得部分执行反馈或延迟确认。
- **单一模型与数据集**：仅在Qwen2.5-7B-Instruct和Spider/BIRD开发集上评估，结果对其他模型系列、规模、多语言场景及生产环境的泛化能力未知。
- **对查询顺序敏感**：记忆构建依赖于流顺序，论文虽用了3个种子，但仍可能未涵盖所有顺序变异性。

- **未与特定Text-to-SQL SOTA系统对比**，重点在于记忆机制的比较，而非追求绝对最佳准确率。
- 缺少嵌入、索引和检索延迟的详细算力开销报告。
