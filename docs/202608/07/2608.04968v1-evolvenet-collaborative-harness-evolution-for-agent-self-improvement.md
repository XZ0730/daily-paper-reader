## 摘要
LLM 代理的能力不仅取决于其模型，还取决于其装备：即构建上下文、调用工具、验证结果并从失败中恢复的可执行程序。近期研究表明，进化装备可以在不更新模型权重的情况下带来持续改进。然而，现有方法假设所有执行经验都可以路由到单一优化器，该优化器沿着一条顺序轨迹进化一个装备。真实的代理生态系统违背了这一假设：用户、组织和环境会产生无法汇聚的孤立经验流，因此最值得学习的经验恰恰是无法直接集中化的经验。我们提出了 EvolveNet，这是一种将经验提取转移到数据端的协同装备进化范式。共享装备被广播到数据本地的代理部署，每个部署在自己的工作负载上进化该装备。只有产生的程序适应性修改被组合成更新后的共享装备并重新分发，从而使每个参与代理继承其他代理发现的操作经验。通过将汇聚边界从原始工作负载转移到学习到的适应性修改，EvolveNet 将工作负载保留在本地，并允许多个进化搜索以降低的串行深度并发进行。由于独立修改的程序无法像模型参数那样进行平均，并且可能在组合时发生冲突，EvolveNet 引入了作用域类型化、证据引导的程序聚合。在涵盖文本到 SQL、数据科学编程、竞赛编程、软件工程和代理工作流的五种设置中，EvolveNet 在所有五种设置中都改进了共享装备，其中在异构工作负载下增益最大，消融实验将改进归因于来自不同代理的适应性修改的组合，而不是在它们之间进行选择。

## Abstract
The capabilities of an LLM agent depend not only on its model but on the harness: the executable program that constructs context, invokes tools, verifies results, and recovers from failure. Recent work shows that evolving the harness yields persistent improvements without updating model weights. Existing approaches, however, assume that all execution experience can be routed to a single optimizer, which evolves one harness along a sequential trajectory. Real agent ecosystems violate that assumption: users, organizations, and environments generate isolated streams of experience that cannot be pooled, so the experience most worth learning from is exactly the experience that cannot be directly centralized. We introduce EvolveNet, a paradigm of collaborative harness evolution that moves experience extraction to the data. A shared harness is broadcast to data-local agent deployments, each of which evolves it on its own workload. Only the resulting program adaptations are composed into an updated shared harness and redistributed, so that every participating agent inherits operational experience discovered by the others. By shifting the aggregation boundary from raw workloads to learned adaptations, EvolveNet keeps workloads local and allows multiple evolutionary searches to proceed concurrently with reduced serial depth. Because independently modified programs cannot be averaged like model parameters and may conflict when composed, EvolveNet introduces scope-typed, evidence-guided program aggregation. Across five settings spanning text-to-SQL, data-science coding, competitive programming, software engineering, and agentic workflows, EvolveNet improves the shared harness in all five, with the largest gains under heterogeneous workloads, and ablations attribute the improvement to composition of adaptations from different agents rather than to selecting among them.

### 2. 论文提出的方法论

EvolveNet 的核心是“本地进化-聚合-再分发”的循环范式，取代了传统的“汇聚数据-集中进化”。

*   **核心思想**: 将经验提取的步骤前移至数据本地端。广播一个共享装备到多个数据本地的客户端，每个客户端在其本地工作负载上独立进化该装备，形成“本地专家”。服务端仅聚合这些程序增量（而非训练数据），形成一个更新的、继承了所有本地经验的新共享装备，并重新广播。
*   **关键技术细节与公式**:
    1.  **并行本地进化**:
        *   在第 `t` 轮，服务器广播共享装备 `h^{(t)}`。客户端 `k` 使用本地进化算子 `E` 在其本地数据 `D^{tr}_k` 上对其进行进化，得到本地专家装备 `h^{(t)}_k = E(h^{(t)}, D^{tr}_k)`。
    2.  **程序聚合挑战**: 程序无法像模型参数那样通过算术平均进行聚合。独立有益的代码修改在组合时可能产生冗余、矛盾或错误。EvolveNet 通过 `作用域类型化、证据引导的聚合` 解决此问题。
        *   **共同基线的程序差分**: 所有客户端均从相同的 `h^{(t)}` 开始，其贡献可由差分 `Δ(t)_k = diff(h^{(t)}, h^{(t)}_k)` 精确表示。
        *   **行为证据**: 客户端在返回 `h^{(t)}_k` 时，附带行为改变证据 `e^{(t)}_k`，记录了相较基线解决了哪些问题 (`F^{(t)}_k`) 和破坏了哪些问题 (`B^{(t)}_k`)。
        *   **作用域分类型组合**: 聚合器将每个客户端的修改分解为独立的“机制 `m`”，并根据证据为其分配合作用域：
            *   `GLOBAL`: 如果机制 `m` 的证据跨多个客户端领域或解决通用性问题，则其被全局采用。
            *   `HOME(d_k)`: 如果机制的益处仅限于特定客户端 `k` 的领域，则其被有条件地保留，仅当输入属于该领域时才激活。
            *   `⊥(Rejected)`: 如果机制仅修复了一个孤立问题。
        *   **命题 1 & 2 (作用域隔离与冲突消解)**: 这两个命题从理论上保证了，如果两个相互冲突的修改被赋予不同的互斥领域作用域，它们可以安全共存于同一程序中，而不会在非自身领域上产生干扰。这是参数空间聚合无法做到的。
    3.  **行为提交与回滚机制**: 聚合生成候选装备 `~h^{(t+1)}` 后，必须在验证集上进行行为检验。只有当新增解决问题的能力 (`F_val`) 不低于导致的问题 (`B_val`) 时，才接受该候选并作为下一轮的共享装备；否则，回滚至上一轮的 `h^{(t)}`。这为聚合质量提供了安全保障。

### 6. 论文的主要结论与发现

1.  **EvolveNet 范式有效**: 在所有五个设定中，通过协同装备进化得到的共享装备都显著优于未进化的装备，也优于保留任何单一最强客户端。
2.  **经验跨主体积累**: 聚合后的共享装备能够保留并继承来自不同本地专家的独特发现。分析显示，90% 的独特本地增益被保留在了聚合装备中，并且产生了任何单一本地轨迹都未曾达到的新行为。
3.  **聚合而非路由**: 性能提升主要来源于将本地发现机制提升为全局行为（`GLOBAL` 作用域），而将领域特定适配保留为条件分支（`HOME` 作用域）在全局提升之上带来了额外增益。这证明了程序组合的价值，而非简单的任务路由。
4.  **并行加速有效**: EvolveNet 的并行本地进化结构允许以受限于最慢客户端（而非其总和）的串行深度，并发探索多个进化轨迹，换取了显著的时间效率提升。
5.  **方法可迁移**: 更换底层大模型后，EvolveNet 的所有定性行为（增益、门控回滚、超越基准）均得以复现。

### 7. 优点

*   **范式创新**: 将经验提取与汇聚解耦，通过汇聚“可执行的程序适应性修改”而非“隐私数据”，为分布式智能体的协同自我改进提供了全新且实用的范式。
*   **精巧的技术设计**: “作用域类型化、证据引导的程序聚合”技术精确地解决了程序组合的核心难题（冲突、干扰），并通过“行为门控”机制提供安全网，理论清晰且实践有效。
*   **极其严谨的实验方法论**: 论文对方法的声音性有极高的自我要求。通过固定缓存、哈希种子和配对检验来控制系统随机性；通过同快照重放将聚合算子与客户端波动分离；明确指出验证分数不能用于排名。这些设计使得结论非常可靠。
*   **深刻的洞察**: 揭示了“作用域隔离”这一性质如何使得分布式程序聚合能够解决参数聚合无法解决的冲突问题。强调了可执行程序本身可以作为一种强大的经验载体。

### 8. 不足与局限

*   **数据局部性不等于隐私**: 论文坦诚地指出，方法只能保证原始数据不离开客户端。但进化的程序修改本身（例如硬编码的数据库表名）可能编码了客户端的私有信息。论文未对信息泄露的威胁模型进行分析。
*   **代码膨胀问题**: 作用域类型化采用添加式聚合，当门控持续通过时，共享装备的代码量会随时间单调增长，缺乏“剪枝”或“淘汰”过时机制的考量。目前仅在 `T≤3` 的轮次内观察。
*   **对领域标识符的依赖**: `HOME` 作用域的有效性依赖于一个可观察的领域分发键（如数据库名、库名），这并非在所有通用场景中都自然存在或容易定义。
*   **有监督设置**: 方法依赖于客户端的本地训练数据和服务器端的验证集标签，是一种有监督的协同适应，与无标签的测试时适应（Test-Time Adaptation）场景设定不同，因此结果不具可比性。
*   **聚合比较的快照局限**: 消融实验中不同聚合规则共享了同一组客户端快照，虽然解耦了客户端方差，但这是一种反事实分析，没有模拟每个规则在多轮中的独立演化路径。
*   **Benchmark 的黄金答案问题**: BIRD 数据集的答案并非完全唯一确定，这可能限制了可达准确率的上限。
